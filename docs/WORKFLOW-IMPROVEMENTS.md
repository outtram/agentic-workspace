## What Was Done

### 1. Single Source of Truth for Help (ELIMINATES the #1 problem)

**Before:** Help maintained in 3 places (HELP.md, `_HELP_TEXT` in app.py, `/help` in router.py). Manual sync. Frequent drift.

**After:** All help generated from `brain/command_centre/help_data.yml`:
- `HELP.md` — generated by `python3 -m brain.command_centre.help_gen`
- `app.py _HELP_TEXT` — generated by same command
- `router.py /help` — reads `help_data.yml` at runtime (no patching needed)

**One file to edit. Zero drift. Zero arguments.**

### 2. Git Pre-Commit Hook

**File:** `.git/hooks/pre-commit` (executable)

**What it validates:**
- If `help_data.yml` changed → runs `help_gen --check` (are outputs stale?)
- If CC files changed but `help_data.yml` didn't → warns about new commands
- Syntax-checks all staged Python files (`py_compile`)
- Runs CC tests if CC files changed and tests exist

### 3. Command Centre Test Suite (17 tests)

**Directory:** `brain/tests/test_command_centre/`

**test_help_sync.py (8 tests):**
- `help_data.yml` exists and is valid YAML
- Every router command is in `help_data.yml`
- Every `help_data.yml` command is in the router
- HELP.md matches `help_data.yml`
- `help_gen --check` passes
- Keybinding sections are not empty
- Agents and skills are documented

**test_router.py (9 tests):**
- `/help` returns content
- Unknown commands return helpful error
- Commands with no selection handle gracefully
- Usage help for `/email` and `/telegram`
- Case-insensitive parsing
- Whitespace trimming

### 4. Claude Code Hooks (5 hooks across 4 lifecycle events)

**SessionStart:** Date, timezone, memory system status
**PreToolUse (Bash):** Blocks `git commit` if help outputs are stale
**PostToolUse (3 hooks):**
- Memory file → remind to update NAVIGATOR.md
- `help_data.yml` → remind to run `help_gen`
- CC Python files → remind to run tests
**Stop:** If CC files staged, runs help check + tests; blocks if failing
**Notification:** macOS notification

### 5. CLAUDE.md Overhaul

**Before:** 118 lines, prose-heavy, instructions buried in paragraphs
**After:** 80 lines, structured checklists, explicit Definition of Done

Key additions:
- **Pre-Commit Checklist** — mechanical verification steps
- **Definition of Done** — what "done" means for CC features
- **Single Source of Truth section** — clear instructions for help system
- Removed: Daily routine details (moved to skills), research foundation (moved to ARCHITECTURE.md)

### 6. GitHub Actions CI

**File:** `.github/workflows/ci.yml`

Runs on push to main/dev/feature branches:
1. Python syntax check (all `.py` files)
2. Help sync check (`help_gen --check`)
3. Command Centre tests
4. Full test suite

## How This Changes the Workflow

### Adding a new Command Centre command

1. Implement handler in `brain/command_centre/handlers/` or `router.py`
2. Add entry to `brain/command_centre/help_data.yml`
3. Run: `python3 -m brain.command_centre.help_gen`
4. Write test in `brain/tests/test_command_centre/`
5. Run: `python3 -m pytest brain/tests/test_command_centre/ -x -q`
6. Commit — pre-commit hook validates everything

### What Happens Automatically

| Event | What fires | What it does |
|-------|-----------|-------------|
| Edit CC Python file | PostToolUse hook | Reminds: update help_data.yml + run tests |
| Edit help_data.yml | PostToolUse hook | Reminds: run help_gen |
| `git commit` with CC changes | PreToolUse hook | **Blocks** if help outputs stale |
| `git commit` | Pre-commit git hook | Validates syntax + help sync + runs tests |
| Claude finishes response | Stop hook | Checks staged CC files are consistent |
| Push to GitHub | CI workflow | Runs all tests + help check |

### What Troy No Longer Has to Do

- "Did you update the help text?" → Automated check blocks bad commits
- "That handler is broken" → Tests catch regressions
- "The help is out of sync" → Single source of truth eliminates drift
- "Run the tests" → Pre-commit hook + CI run them automatically
